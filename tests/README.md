# Tests boundary

单元测试、匿名 fixtures 与后续端到端测试分别放在此目录下的对应子目录中。

`fixtures/steam/` 仅使用虚构昵称、测试域名与合成标识，不得加入真实玩家的完整响应。Phase 2A 单元测试覆盖身份解析、Steam 客户端边界和快照标准化；Phase 2B 测试覆盖 Route Handler、HTTP 错误映射、缓存策略、密钥隔离和首页错误展示规则。

`fixtures/report.ts` 提供普通玩家、千小时单推、500+ 库存、空库存、纯零时长、超长中文昵称和称号冲突等合成样本。Phase 3 测试覆盖所有报告指标、确定性排序、分组边界、Steam 年龄和称号优先级。

Phase 4 测试使用 jsdom 和 Testing Library 覆盖首页成功结果写入会话并导航、报告与页码恢复、损坏存储清理、存储权限失败、按钮与方向键翻页、横向滑动、焦点移动、最后一页反馈和头像加载失败。多视口视觉检查不由 jsdom 代替；已在 Chrome 中使用合成报告检查 320、375、414、768 与 1280px，320px 覆盖全部 10 页。

Phase 5 测试覆盖确定性星图布局、1/20/100/500 款库存、零时长未点亮状态、长尾星云聚合、边界与非重叠约束，以及 500 款库存的纯函数性能预算。Canvas 视觉与星云选择交互使用同一份 500 款合成报告在 Chrome 中核验。

Phase 6 测试覆盖海报固定 1080 × 1440 画布契约、首页二维码不含 SteamID、Steam 图标 URL 推导和外部图片失败时的资产降级。播放器测试覆盖生成成功后的 PNG 预览与下载入口，以及生成失败时保留报告并可重试。Chrome 使用合成报告生成实际 PNG 并进行固定尺寸截图视觉核验；实体手机扫码属于 Phase 9 真机验收。

Phase 7 测试覆盖 Steam OpenID `checkid_setup` 请求、固定回调/`realm`、一次性状态 Cookie、直接 `check_authentication` 验证、取消与超时/验证失败边界，以及验证成功后通过两分钟 HttpOnly SteamID Cookie 复用既有 `ReportData` 接口。测试不会调用真实 Steam 登录或保存任何账号会话。

Phase 8 测试覆盖无效 ID、私密库存、Steam 超时和空库存的不同前端操作；头像失败时的可见首字降级；超长中文昵称的完整可访问文本；以及海报失败后不丢失报告并可重新生成。Chrome 以匿名报告检查了长昵称无横向溢出、头像降级说明和固定尺寸海报中的两行省略。

Phase 9 浏览器验收使用匿名 500 游戏报告检查 320、375、414、768px 的总览、星图与海报页面。各宽度没有横向溢出；`100dvh` 报告区域高度与视口一致；可见控件最小高度为 44px。500 游戏星图在 320px 可点按选中星体，长尾聚合为 400 款星云；实际海报为 1080 × 1440 PNG，二维码源尺寸为 218 × 218px。详情和真机遗留项见 `docs/mobile-acceptance.md`。
