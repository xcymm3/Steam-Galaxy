# 游戏星系规格

- 状态：Accepted
- 版本：1.0
- 日期：2026-07-24

## 1. 产品契约

游戏星系是玩家当前公开 Steam 数据形成的可探索快照，不是逐年历史档案，也不是年度报告。

- 首页成功读取后只进入一个星系工作台，不存在分页故事或自动播放。
- 所有游戏都被表达：前 100 款以独立可选天体出现，其余游戏以长尾档案信号聚合。
- 用户可拖动、缩放、点击或通过键盘聚焦独立天体。
- 所有数值来自 Steam 数据或明确、可测试的派生计算。
- 无法验证的购买动机、夜间游玩和历史口味变化不进入产品文案。
- 产品不生成玩家海报，也不提供永久报告链接。

## 2. 概念数据模型

### Player

| 字段         | 必需 | 用途                             |
| ------------ | ---- | -------------------------------- |
| SteamID64    | 是   | 服务端读取数据，不在工作台中展示 |
| 昵称         | 是   | 工作台标题与可访问标签           |
| 头像         | 否   | 登录结果确认；失败时使用首字降级 |
| 资料 URL     | 否   | 返回 Steam 个人资料页            |
| 账号创建时间 | 否   | 报告指标；不是星体大小的输入     |

### Owned Game

| 字段         | 必需 | 用途                                     |
| ------------ | ---- | ---------------------------------------- |
| AppID        | 是   | 游戏唯一标识与按需商店元数据查询键       |
| 名称         | 是   | 星体标签、详情面板与读屏文本             |
| 累计游玩分钟 | 是   | 独立天体排序、物理体积、轨道和明暗       |
| 图标标识     | 否   | 基础 Steam 封面 URL 的降级来源           |
| 最近游玩时间 | 否   | 保留在数据模型，不推导未经验证的历史结论 |

### Galaxy Model

| 字段             | 规则                                                 |
| ---------------- | ---------------------------------------------------- |
| `nodes`          | 最高时长 100 款游戏，按分钟降序、AppID 升序稳定排序  |
| `physicalRadius` | 与累计游玩时长的立方根映射，保持体积与时长严格成正比 |
| `longTail`       | 第 101 款及以后游戏的数量、时长与未游玩数量聚合      |
| `kind`           | 有时长为行星，0 小时为弱档案信号                     |
| `scene`          | 由轨道带、镜头焦点和渲染参数组成，不含 React 状态    |

因此，1000 小时游戏对应 100 小时游戏的 10 倍体积；视觉阴影、纹理与发光不能改变这个物理比例。

## 3. 工作台交互契约

- 工作台顶部显示当前玩家、累计时长、已点亮游戏数和可选星体数。
- 星图区域是主要操作面：拖动旋转视角，滚轮/双指缩放，点击星体选择。
- 键盘可在已选星体间移动并重置视角；焦点移动时镜头平滑靠近目标。
- 选中后展示名称、封面、累计时长、AppID 和明确的星体状态。
- 详情首先使用已知基础数据；再按需读取公开 Steam 商店元数据，展示类型、系列、单人/多人/合作模式等字段。
- 商店元数据加载中、不可用、封面失败与重试都必须有可见文本，不能阻塞星图继续浏览。
- `prefers-reduced-motion` 下取消镜头和环境的非必要连续动画。

## 4. 数量与降级策略

| 条件                   | 呈现                                          |
| ---------------------- | --------------------------------------------- |
| 1–100 款游戏           | 每款均为独立天体或档案信号                    |
| 超过 100 款游戏        | 保留前 100 个独立节点，其他游戏为长尾档案信号 |
| 全部游戏为 0 小时      | 不生成误导性大小排序，以未点亮档案状态解释    |
| 没有可恢复的标签页会话 | 显示返回首页、重新读取游戏库的恢复界面        |
| WebGL 不可用           | 显示可读降级说明和基础星系统计                |
| 商店接口不可用         | 保留游戏名称、时长、AppID 与重新查询入口      |

相同的 SteamID、AppID 集合与时长必须产生相同的节点顺序和场景归属；禁止使用未设种子的随机布局。

## 5. 数据诚信规则

允许：

- “你累计玩了 3421 小时。”
- “《某游戏》拥有 155.4 小时，因此体积为 100 小时游戏的 1.554 倍。”
- “其余 423 款游戏收束在长尾档案区。”

禁止：

- “这款游戏吞掉了你最多的夜晚。”
- “你在 2021 年从 FPS 转向 RPG。”
- “这些游戏买下时很期待，后来再没打开。”
- “你和朋友共同经历了这段游戏时期。”

## 6. 必测样本

- 无效 SteamID、私密游戏详情和空库存。
- 只有 1 款游戏、少于 100 款、恰好 100 款和 500 款以上库存。
- 全部游戏为 0 小时，以及单款游戏超过 10000 小时。
- 极长中文、英文和 Emoji 昵称。
- 游戏封面或商店元数据无法加载。
- 键盘聚焦、拖动、缩放、重置焦点与减少动态效果。
- 320、375、414、768 和桌面宽度的无横向溢出与可达控件。
