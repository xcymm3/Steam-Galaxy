# ADR-0003：全库参与的 Steam 星系模型

- 状态：Accepted
- 日期：2026-07-24

## 背景

产品从十页游戏生涯报告转为单页可探索星系。Steam 库可能包含数百甚至数千款游戏；把每款游戏都作为完整材质行星渲染，会降低移动端性能与可读性。

同时，0 小时游戏不能诚实地拥有“按时长成比例”的行星体积：其体积应为 0。

## 决策

1. 每次读取完整公开游戏库，并按累计游玩分钟降序、AppID 升序排序。
2. 前 100 款游戏成为独立、可点选的星系对象。
3. 累计时长大于 0 的对象为行星。半径与累计小时的立方根成正比，因此球体体积严格与累计时长成正比。
4. 累计时长为 0 的前 100 款对象为“档案信标”：可点选，但不以虚假的行星体积表示。
5. 100 名之后的游戏不生成独立档案面板；它们汇总为长尾星尘，并保留游戏数、已玩数、未玩数和累计时长。
6. 商店元数据和封面不进入初始星系模型。用户点选某颗独立星球时再按需获取并缓存。

## 结果

- 所有公开游戏都对星系总量和长尾统计有贡献。
- 至多 100 个独立可交互对象，保证场景、拾取和移动端面板可控。
- 不把未游玩游戏伪装为具有时长体积的行星。
- 未来的 Three.js 布局、筛选和档案面板都依赖 `GalaxyModel`，不再依赖“太阳、八大行星、冥王星”的固定角色。
