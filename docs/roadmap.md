# 实施路线图

- 状态：Phase 9 浏览器验收完成；真实公开账号、实体手机扫码与低性能真机验收 pending
- 日期：2026-07-22

本路线图按“先形成真实数据闭环，再完善视觉”的顺序推进。每个阶段都应满足退出条件后再进入下一阶段。

## Phase 0：架构确认

状态：Completed（2026-07-21）。

交付物：

- 系统架构文档。
- 报告规格。
- 无数据库 ADR。
- Steam 数据边界 ADR。

退出条件：

- 模块职责没有重叠。
- 10 页报告的指标与降级策略明确。
- 明确哪些内容不做。
- 用户确认可以开始初始化工程。

目标：建立可以运行但没有业务功能的 Next.js 工程。

计划内容：

- 初始化 TypeScript + React + Next.js App Router。
- 建立 lint、format、test 和 build 命令。
- 建立 `app`、`components`、`lib`、`styles`、`tests` 边界。
- 建立设计 token 文件，但不实现完整页面。
- 配置环境变量契约，不提交真实密钥。

退出条件：

- [x] 空应用可开发、测试和构建。
- [x] CI 能执行格式、lint、类型检查、单元测试和构建。
- [x] 目录依赖方向符合架构文档。
- [x] 320、375、414、768 与 1280px 基础页面无横向滚动。

## Phase 2A：Steam 数据内核

状态：Completed（2026-07-21）。

目标：不依赖页面或真实密钥，建立可独立测试的 Steam 快照生成内核。

已完成：

- SteamID64、自定义 ID 和个人资料 URL 解析。
- Steam Gateway 与超时处理。
- 玩家资料和公开游戏库读取。
- 第三方响应 schema 校验。
- 私密库存、无效 ID 和上游错误归一化。
- 建立不包含真实个人信息的测试 fixtures。
- 对可用游戏按累计时长和 AppID 确定性排序。
- 对畸形游戏条目保留跳过数量诊断。

退出条件：

- [x] 模拟公开账号响应可以生成稳定 `SteamSnapshot`。
- [x] 私密库存不会被误判为空库存。
- [x] API Key 不进入请求 URL，客户端只访问硬编码 Steam 主机。
- [x] 数据内核不依赖 React、Next.js 路由或数据库。

## Phase 2B-1：服务端产品接线

状态：Completed（2026-07-21）。

目标：通过统一的 Next.js 服务端接口调用 Phase 2A 数据内核。

已完成：

- 创建 `POST /api/steam/report` Route Handler。
- 只从服务端环境变量读取 `STEAM_WEB_API_KEY`。
- 验证接口响应使用 `no-store` 策略。
- 统一成功与失败 JSON 契约。
- 将内部错误码映射为稳定 HTTP 状态。
- 使用匿名 fixtures 测试公开、私密、限流和配置缺失路径。

退出条件：

- [x] 模拟公开账号可通过 Route Handler 生成稳定 JSON。
- [x] 私密库存不会被误判为空库存。
- [x] 所有响应均声明 `Cache-Control: private, no-store`。
- [x] API Key 仅由服务端读取，并且不进入 Steam 请求 URL。

目标：完成固定尺寸、可分享且不携带 SteamID 的报告海报。

已完成：

- [x] 由浏览器 Canvas 直接生成固定 1080 × 1440 PNG，不把报告或 SteamID 发送到额外海报接口。
- [x] 按顺序绘制文字与数字、头像、Top 3 游戏图标、二维码和简化星图。
- [x] 二维码只指向部署域名的首页，路径、查询参数、片段和 SteamID 均不会写入二维码。
- [x] 下载始终可用；浏览器支持 Web Share Files 时提供系统分享。
- [x] 头像、游戏图标或最终 Canvas 编码失败时，回退为可下载的纯文字/编号海报。
- [x] 单元测试锁定 1080 × 1440 尺寸、二维码目标与资产降级；Chrome 已生成合成报告并捕获固定尺寸海报截图进行视觉核验。

退出条件：

- [x] 海报在外部图片失败时仍能生成。
- [ ] 二维码在实际手机上可识别（Phase 9 与真机验收一并完成）。

## Phase 7：Steam OpenID

状态：Implementation completed（2026-07-22）；等待真实 Steam 账号联调。

目标：在不建立账户系统的前提下支持 Steam 登录。

已完成：

- [x] 提供登录发起、回调和一次性消费三个无状态 Route Handler。
- [x] 使用 10 分钟随机状态 Cookie；生产 HTTPS 发送 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- [x] 回调固定 Steam OpenID Provider、`realm`、`return_to` 与 Claimed ID，并以 `check_authentication` 向 Steam 二次验证断言。
- [x] 验证成功后仅把 17 位 SteamID 放入 2 分钟 HttpOnly Cookie；消费后立刻删除，复用既有 `ReportData` API 响应。
- [x] 在首页提供 Steam 登录入口及取消、过期、超时、验证失败和配置错误提示。
- [x] 单元测试覆盖请求参数、状态 Cookie、回调验证、取消、回放后的缺失 Cookie 与现有报告链路接通。

退出条件：

- [x] 登录不会绕过游戏详情隐私设置。
- [x] 回调不可被伪造或重放：状态 Cookie 与已验证 SteamID Cookie 都是短时效、单次消费。
- [x] 不产生用户表或长期会话依赖。
- [ ] 使用真实 Steam 账号完成生产 `APP_ORIGIN`、回调和公开库存联调。

## Phase 8：异常状态

状态：Implementation completed（2026-07-22）；真实 Steam 账号与真机状态留待后续验收。

目标：让无效输入、隐私限制、上游故障与图片或海报降级都具有明确、可恢复的前端反馈。

已完成：

- [x] 以稳定错误码区分无效 ID、私密库存、空库存、Steam 超时、限流、配置错误与 OpenID 失败，并维持 API `no-store`。
- [x] 首页为无效 ID、私密库存、Steam 超时与空库存分别提供可理解的标题、原因和下一步操作；可重试项保留原输入。
- [x] Story Player 在头像 URL 缺失或加载失败时使用 Unicode 安全的昵称首字，并显示可见降级说明。
- [x] 超长中文昵称保留完整的可访问文本；报告页面自动换行，固定尺寸海报限制为两行并以省略号收束。
- [x] 海报图片、Canvas 或编码失败不会丢失报告，用户可重试；外部图片不可用时仍可下载文字/编号降级 PNG。
- [x] 单元测试覆盖所有关键 API 呈现、头像失败、超长昵称、空库存和海报失败后的重试；Chrome 使用匿名合成报告确认无横向溢出和海报长昵称降级。

退出条件：

- [x] 每个错误码都映射到一致、可恢复的前端状态。
- [x] 图片与海报失败不会阻断报告阅读或下载替代方案。
- [x] 公开的空库存不再被误导为私密库存。

## Phase 10：公开发布

目标：可安全地作为作品集项目公开访问和开源。

计划内容：

- 选择并配置部署平台。
- 配置正式回调 URL 和首页二维码 URL。
- 添加隐私说明、数据来源和非 Valve 官方声明。
- 添加无个人信息的错误观测。
- 添加基础限流或挑战机制。
- 完成 README、部署说明和贡献说明。

退出条件：

- GitHub 仓库不含密钥和真实玩家 fixtures。
- 线上 Steam 登录和海报下载可用。
- 上游故障不会暴露内部错误或无限重试。
- 移动端 Lighthouse 与人工体验达到发布标准。
